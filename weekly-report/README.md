# 周报生成 Skill

根据当周工时截图和公司周报模板，先核对并展示完整预览；你确认预览后，再生成保留模板格式的 DOCX。

## 一条 Prompt 安装并使用

把**公司周报模板 DOCX**和**本周工时登记截图**附在同一条消息中，然后复制下面整段 Prompt 发给支持 Agent Skills、能访问 GitHub 并处理 DOCX 的 AI 助手。不需要填写电脑路径、打开终端或提供上一周周报。

```text
请先检查 `weekly-report` 是否已经安装并可用。如果尚未安装，请使用你支持的 Agent Skills 安装方式，从下面的 GitHub 地址安装并启用整个 `weekly-report` 目录（包括 `SKILL.md` 和脚本）；如果已经安装，请直接使用当前版本，不要覆盖其他来源的本地技能或修改。安装或确认已有安装后，读取该 Skill 的 `SKILL.md` 并处理我附加的文件：

https://github.com/wtwang1998/my-skills/tree/main/weekly-report

把本消息附带的 DOCX 作为公司周报模板，把工时登记截图作为当周输入。先核对信息并给我完整预览；信息缺失或矛盾时，先集中询问我。只有我明确确认最新预览后，才生成 DOCX。不要要求我手动查找安装目录或执行命令。如果你无法访问该 GitHub 地址、安装 Skill 或生成 DOCX，请如实说明具体受限步骤，不要声称已经安装或生成。
```

上面的链接对应本仓库 `main` 分支中的技能目录；本次更改推送到 GitHub 后即可通过该链接安装。

## 你需要准备

- **公司周报模板**：DOCX 格式，包含周报栏目和表格。
- **当周工时截图**：尽量清晰、完整地显示日期、工时类型、项目、汇报工时、工作描述和工时合计。表格较长时，可以附多张带重叠行的截图。

无需附上上一周周报。模板里的姓名、岗位、部门或负责人会直接沿用；其他缺失信息由助手在核对时询问。

## 处理和确认方式

1. 助手逐条读取截图，并核对报告周期、记录数量和实际工时合计。
2. 如果项目名称、项目编号、工作地点、出差、下周计划或其他必填信息不清楚，会先询问补充；工时合计有矛盾时会暂停并请你核实。
3. 信息充分后，助手展示完整预览，包括全部日记录、核心产出、计划偏差、困难及所需支持、下周计划和其他反馈事项。
4. 你可以直接指出需要调整的内容。助手修改后重新展示完整预览。
5. 只有你确认最新预览后，助手才生成 DOCX。默认不覆盖已有文件；需要覆盖时请明确指出要覆盖的文件。

## 项目命名和内容规则

- 项目名称格式为 **类别-公司名-正式项目名（项目编号）**；类别只能是“临床试验”“CER”“技术支持”“其他”。
- 项目编号只使用你明确提供或确认的编号。截图中的 `SMJC-YW-2026-03` 不作为周报项目编号，`CTO-GCP` 不属于项目名；缺少已确认编号时省略编号和括号。
- 工作内容和产出/结果根据截图中的“工作描述”及你补充的信息整理，不从“项目任务”“工时场景”或“任务执行组织”推断。
- 非项目事项标为“其他-具体事项”。调休写“其他-调休”，工作内容写“调休，无工作”，结果写“—”。
- 核心产出和下周计划都要写出对应的完整项目名称。没有特定关联中心时填“—”。
- DOCX 遵从模板格式，文字颜色统一为黑色；生成后逐页检查版面。若当前助手无法渲染检查，会如实说明。
